# Physical Admission and Organizational Realization

## 1. Starting Point

A realized world contains many physically possible transitions.

A particular organization realizes only a restricted subset of them.

This suggests a basic distinction:

```text
physics
->
space of possible transitions
```

```text
organization
->
subset of transitions actually realizable
under specified conditions
```

A mathematical description, social expectation, task specification, or imagined goal does not itself create a capability.

A capability exists only when some organization can physically realize the relevant interaction chain.

The central question is therefore not:

```text
What can be described?
```

It is:

```text
What can this organization realize,
from this state,
under these conditions,
with these resources,
within this time,
and with what consequences for later capability?
```

This shifts attention from abstract possibility to organized realizability.

---

## 2. Physics Admits; Organizations Realize

Physics determines what is not forbidden in principle.

Organizations determine which physically possible transitions occur reliably, repeatedly, and controllably.

For example:

```text
physics admits computation
```

but:

```text
a CPU realizes particular computational transitions
```

```text
physics admits powered flight
```

but:

```text
an aircraft realizes controlled flight
```

```text
physics admits sound detection over many frequencies
```

but:

```text
a particular auditory organization realizes only a limited range
```

The difference is not philosophical superiority.

It is implementation.

An organization either contains the structures required to realize a transition family or it does not.

---

## 3. Possibility, Realizability, and Maintainability

Three levels should be distinguished.

### Physical possibility

A transition is compatible with the governing physical laws.

### Organizational realizability

A particular organization can produce the transition under some admissible conditions.

### Persistent realizability

The organization can produce the transition repeatedly while remaining capable of future realizations.

Schematically:

```text
physically possible
does not imply
realizable by this organization
```

```text
realizable once
does not imply
reliably repeatable
```

```text
repeatable for a while
does not imply
indefinitely maintainable
```

This hierarchy prevents arbitrary goals from being confused with empirical capabilities.

A human may describe unaided flight, ultrasonic hearing, or indefinite survival without oxygen.

The descriptions are meaningful.

The capabilities are not thereby realized.

## 4. Capability Landscapes

Let an organization be denoted by:

\[
O
\]

Its capability landscape may be represented as:

\[
\mathcal{C}(O)
=
\{\text{interaction families realizable by }O\}
\]

This landscape is constrained by:

```text
morphology
materials
energy supply
sensing
actuation
memory
computation
control structure
environment
maintenance
```

A capability is therefore relational.

It is not simply a property of the organization in isolation.

For example:

```text
vehicle traversal
```

depends on:

```text
vehicle organization
+
terrain organization
+
weather
+
load
+
legal conditions
+
operator capability
```

The relevant capability is the realized relation among these factors.

## 5. Tasks and Values Are Not Capabilities

A task may be described whether or not any existing organization can realize it.

Let:

\[
\mathcal{T}
=
\text{the set of describable tasks}
\]

Then:

\[
\mathcal{C}(O)\subseteq\mathcal{T}
\]

A society, designer, agent, or institution may select a valued subset:

\[
V\subseteq\mathcal{T}
\]

But this selection does not guarantee realizability.

```text
valued
does not imply
possible
```

```text
possible
does not imply
realizable by the current organization
```

```text
realizable
does not imply
maintainable
```

This distinction matters whenever an organization is judged by a metric that lies outside its realizable or maintainable capability region.

---

## 6. Admissible Regions Are Capability-Relative

Admissibility is not absolute.

A state is admissible only relative to some capability, task, query, or future interaction family.

Let:

\[
K_c\subseteq X
\]

be the set of states from which capability \(c\) remains realizable.

Then:

```text
state x is admissible for c
```

means:

```text
from x,
the organization can still realize c
under the specified conditions
```

The ordering is therefore:

```text
physical organization
->
capability landscape
->
selected task or query
->
admissible region
```

For hearing, the relevant question is not whether a person can detect arbitrary frequencies.

It is which frequencies the auditory organization can detect within its realized operating range and tolerance.

An expectation outside that range is not evidence of failure inside the capability landscape.

It is a mismatch between task and organization.

---

## 7. Recovery Is an Implemented Transition

Recovery is not a universal tendency.

It exists only when the organization realizes a transition from deviation back into an admissible region.

```text
deviation
->
detection
->
corrective transition
->
re-entry into admissible region
```

If no such mechanism exists, recovery does not occur.

A software analogy makes this clear.

```text
exception
+
implemented handler
->
recovery path
```

```text
exception
+
no handler
->
unhandled transition,
termination,
or propagation
```

The absence of a handler is not morally inferior.

The relevant recovery transition is simply not implemented.

The same applies to cells, machines, institutions, and organisms.

---

## 8. Rocks, Cells, and Structural Pressure

A rock and a cell both obey physics.

Both undergo change.

Both may persist for some time.

But they differ structurally.

A rock may remain intact because environmental conditions do not yet destroy it.

A cell actively realizes processes such as:

```text
ion regulation
protein synthesis
waste removal
membrane maintenance
energy conversion
damage detection
repair
```

The difference is not that the rock violates persistence.

The difference is that the cell contains organized feedback loops that repeatedly restore conditions required for its characteristic interactions.

Thus:

```text
passive persistence
!=
active maintenance of capability
```

A cell is not metaphysically superior to a rock.

It is differently organized.

Words such as:

```text
pressure

goal
```

can introduce unnecessary teleology.

A more structural description is:

> The organization contains mechanisms whose activation changes behavior when task-relevant variables approach or cross specified ranges.

Examples include:

```text
rising CO2
->
air hunger
->
breathing or surfacing behavior
```

```text
dehydration
->

water-seeking behavior
```

```text
position error
->

->

```

```text
temperature below threshold
->
heater activation
```

The organization does not need an abstract philosophical commitment to survival.

It realizes particular feedback transitions.

The experienced pressure to breathe, eat, drink, sense, think, or act is one manifestation of those implemented dynamics.

## 10. Life, Death, and Protected Organization

Life is difficult to define independently of the transitions that terminate or destroy living organization.

Likewise, admissibility is difficult to define independently of inadmissibility.

A boundary matters because crossing it changes future realizability.

```text
inside region
->
capability remains realizable
```

```text
outside region
->
capability is degraded, lost, or recoverable only at additional cost
```

Humans do not protect arbitrary persistence equally.

They protect particular organized capacities:

```text
metabolism
memory
agency
relationships
language
learning
future action
pain avoidance
social continuity
```

This explains why rocks, cells, mice, and humans are not treated as equivalent even though all are physically realized organizations.

The protected object is not bare existence.

It is a selected organization of capabilities and future trajectories.

## 11. Social Judgments and Capability Projections

Terms such as:

```text

```

usually project a narrow task set onto an entire organization.

The implicit structure is:

```text
cannot realize capability c
within valued set V
```

compressed into:

```text

```

These are not equivalent statements.

A person may be inadmissible for one task and highly capable for another.

The judgment depends on:

```text

social expectations
resource structure
institutional design
available assistance
```

The capability landscape may be empirically constrained.

The valuation imposed on it may be contingent, unstable, or unrealizable.

## 12. Reusable Structures Solve Families of Inverse Problems

A forward problem asks:

```text
given organization and input,
what follows?
```

An inverse problem asks:

```text
given desired outcome,
which realizable organization,
state,
policy,
trajectory,
or control input
can produce it?
```

Many practical tasks are inverse problems.

```text
desired end-effector pose
->
joint trajectory
```

```text
desired destination
->
route
```

```text
desired output
->
program or circuit activity
```

```text
desired prediction accuracy
->
parameter update
```

A bounded organization rarely solves these problems from raw physical detail every time.

It reuses intermediate structures.

To travel from Berlin to Munich, people do not ordinarily explore Germany from scratch.

They reuse:

```text

```

The route is then calculated relative to:


The route itself is transient.

The local steering commands are more transient still.

```text
road topology
->
route
->
maneuver
->
actuator command
```

This is a hierarchy of relative persistence.

An abstract edge such as:

It is not merely graph connectivity.

## 15. Kinematics, Jacobians, and Local Structure

For a robot:

\[
x=f(q)
\]

where:

```text
q = joint configuration
x = end-effector state
```

The Jacobian:

\[
J(q)=\frac{\partial f}{\partial q}
\]

describes local sensitivity.

It answers:

```text
how will a small change in joint configuration
change the end-effector state?
```

The Jacobian is not a complete inverse solution.

It is a local computational intermediate.

Because it depends on the current configuration, it is often recalculated rather than stored for every possible state.

The more persistent reusable structure is usually:

```text
robot geometry
+
kinematic model
```

from which the transient Jacobian can be derived.

---

## 16. Backpropagation as Sensitivity-Based Inverse Approximation

Forward propagation computes:

\[
x
\rightarrow
y
\]

Training asks:

```text
which parameter changes
would reduce the discrepancy
between current and desired behavior?
```

This is an inverse problem.

Backpropagation does not compute an exact inverse.

It efficiently computes local sensitivities:

\[
\frac{\partial L}{\partial \theta}
\]

where \(L\) is a loss and \(\theta\) the parameters.

This allows iterative updates:

```text
current organization
->
measured error
->
sensitivity
->
parameter change
->
new organization
```

Backpropagation is therefore a mechanism for navigating a capability landscape through local differential information.

## 17. Gradient Detection and Consequential Change

A gradient does not simply identify what changes fastest in time.

It identifies directions in which a selected quantity is most sensitive to change.

For:

\[
f(x)
\]

the gradient:

\[
\nabla f(x)
\]

indicates how local perturbations of \(x\) affect \(f\).

In a broader operational sense:

```text
small change in variable
+
large change in task-relevant outcome
->
important distinction
```

This connects directly to representation pressure.

A bounded organization benefits from detecting which changes alter:

```text
prediction
reachability
stability
error
resource cost
future capability
```

Gradient-based methods are one implementation of this broader sensitivity principle.

## 18. Nothing Is Absolutely Invariant

Kinematic equations may appear fixed.

But realized robots change through:

```text
thermal expansion
wear
backlash
compliance
sensor drift
part replacement
damage
```

Maps also change.

Bodies age.

CPUs heat and degrade.

Social conventions evolve.

Scientific models lose accuracy.

Therefore, reusable structures should not be treated as absolutely invariant.

A better concept is:

```text
validity horizon
```

or:

```text
regularity lifetime
```

Let:

\[
\tau(R,Q,\varepsilon)
\]

denote the interval or interaction range over which representation \(R\) remains sufficiently accurate for query set \(Q\) within tolerance \(\varepsilon\).

Reuse is justified when:

```text
cost of reusing and maintaining R
<
cost of reconstructing the relevant structure from scratch
```

## 20. Why Computational Intermediates Arise

Suppose every task had to be solved directly from raw physical detail.

```text
current total state
->
desired total state
```

The search space would be enormous.

Instead, organizations factor problems into intermediate structures:

```text
geometry
kinematics
dynamics
maps
features
latent variables
concepts
coordinates
policies
Jacobians
graphs
```

These intermediates are useful when they:

```text
remain valid across many tasks
reduce search
reduce communication
support composition
permit local correction
separate slow from fast variation
```

The pressure is not merely toward compression.

It is toward representations that make repeated inverse problems tractable.

## 25. Models Also Have Admissibility Regions

A model is itself a maintained reusable organization.

It remains useful only while its predictions satisfy task-relative tolerances.

```text
world changes
->
model error grows
->
prediction or control fails
->
recalibration, retraining, revision, or replacement
```

Thus:

```text
physical organizations have admissible regions
```

and:

```text
models have admissible regions
```

A map can become inadmissible for navigation.

A calibration can become inadmissible for precision control.

A neural model can become inadmissible under distribution shift.

A legal rule can become inadmissible for a changed institution.

This recursion is central.

The structures used to preserve admissibility must themselves be maintained.

## 26. A Minimal Formalization

Let:

\[
X
\]

be a realized state space,

\[
U
\]

a control space,

\[
F
\]

a transition relation or dynamics,

\[
O
\]

a physically realized organization,

and:

\[
Q
\]

a family of supported queries or tasks.

A capability \(c\) is a family of trajectories realizable by \(O\) under specified environmental and resource conditions.

An admissible region is:

\[
K_c
=
\{x\in X:
c \text{ remains realizable from }x\}
\]

A recovery mechanism is a policy:

\[
\pi_r
\]

such that, for some deviations \(x\notin K_c\) or near its boundary:

\[
\pi_r
\]

produces trajectories returning the organization to:

\[
K_c
\]

with acceptable probability, cost, and time.

A model \(M\) is adequate while:

\[
d(q(x),\hat q(M(x)))\leq\varepsilon
\]

for supported queries \(q\in Q\).

Its validity horizon is the range over which this condition remains satisfied.

## 28. Core Principles

### Principle 1: Physics admits; organizations realize

Physical possibility does not imply organizational capability.

### Principle 2: Capabilities are empirical and relational

They depend on organization, environment, resources, conditions, and tolerances.

### Principle 3: Tasks and values do not create capabilities

A desired or socially valued transition may be unrealizable or unmaintainable.

### Principle 4: Admissibility is capability-relative

A state is admissible only with respect to specified future interactions.

### Principle 5: Recovery must be implemented

Without a realized corrective transition, no recovery occurs.

### Principle 6: Structural pressure is not teleological

Organisms and machines need not philosophically value persistence; they may simply embody feedback mechanisms that restore selected variables.

### Principle 7: Reusable structures solve families of inverse problems

Maps, models, graphs, Jacobians, concepts, and policies reduce repeated search.

### Principle 8: Nothing practical is absolutely invariant

Reusable structures have finite validity horizons and require maintenance.

### Principle 9: Hierarchies reflect relative persistence

Slow-changing relations support faster-changing computations and control episodes.

### Principle 10: Boundedness creates pressure for factorization

A bounded organization cannot operate directly over the full realized capability space at every moment.

### Principle 11: Direct low-level realization may be possible but prohibitively costly

Intermediate layers reduce specification, coordination, computation, and maintenance burdens.

### Principle 12: Models are also organizations under admissibility constraints

They remain useful only while their task-relevant predictions remain within tolerance.

## 30. Design Target

The design target is a representation and control system in which:

```text
physical possibility is separated from organizational realizability
```

```text
capabilities are learned from realized interaction
```

```text
admissible regions are derived relative to supported tasks
```

```text
recovery is represented as an implemented transition family
```

```text
abstract goals remain grounded in realizable trajectories
```

```text
reusable intermediates reduce repeated inverse-problem cost
```

```text
slow-changing structures support faster-changing control
```

```text
models carry explicit validity conditions and tolerances
```

```text
drift triggers recalibration, maintenance, retraining, or replacement
```

```text
value judgments remain distinct from capability claims
```

The central claim is:

> Physics defines a space of possible transitions, but particular organizations realize only constrained subsets of that space. Bounded organizations facing repeated inverse problems benefit from reusable intermediate structures that separate relatively persistent relations from faster-changing states and actions. These structures remain useful only within finite task-relative validity regions and must themselves be maintained, recalibrated, or replaced as the organizations and environments they model continue to change.

The world does not solve abstract goals directly.

Physical organizations realize trajectories.

The organization does not recover because recovery is universally preferred.

It recovers only when corrective transitions are implemented.

A model does not remain valid because it is timeless.

It remains valid while its distinctions continue to support successful interaction.
